## F-0005: TorchVision Resize Half-Boundary Drift

Status: Resolved implementation defect.

Context:
Early Rust resize candidates matched most pixels but diverged at a small number of uint8 half boundaries in tiled canvases and thumbnails. Fixed-point weights and a single accumulation strategy were not sufficient evidence of pinned TorchVision parity.

Expected:
All required processor tensors must match the pinned oracle, and direct byte regressions must cover the boundary pixels rather than relying on plausible normalized output.

Resolution:
Captured the pinned CPU kernel's separable F32 behavior, including contracted short vertical windows, scalar long-window accumulation, ties-to-even rounding, and a one-ULP shadow guard for exact half ties. The direct 7×5 to 8×4 regression now matches all 96 RGB bytes, all 12 processor cases pass with worst normalized maximum absolute error `1.192092896e-7`, and fresh fixture regeneration is byte-identical.
